Intermediate · 45 Minutes

Review Me, Review Me Not, Review Me

Prepare locally. Delegate deliberately. Validate in the cloud.

This course is about the complete agentic delivery loop, not a catalog of review products. Learners will begin with an ambiguous task, improve the repository and task for autonomous execution, hand a plan from VS Code to Copilot cloud agent, and use GitHub security as a feedback system. The final decision remains with a human reviewer.
Challenge

Ship Without Losing Control

A teammate left an underspecified issue. Your mission is to turn it into an agent-ready task, delegate it to the cloud, and bring the resulting pull request through security and human review.

Starting State

Ambiguous scope, undocumented commands, incomplete tests, and no explicit security boundary.

Done State

Reproducible setup, bounded handoff, validated pull request, resolved security findings, and human approval.

Present this as one continuous scenario. The challenge is not simply to make the agent produce code. It is to preserve intent and control while execution moves between local and cloud environments. Ask learners which part of the starting state would create the most expensive failure in their own repositories.

What You Will Be Able to Do

  • Choose between local, background, and cloud execution
  • Optimize a repository and task before delegation
  • Transfer a local plan into a cloud agent session
  • Supervise cloud execution without micromanaging it
  • Route CodeQL findings into agentic remediation
  • Return work to local validation and human-controlled merge
These are operational outcomes. The learner should leave with a repeatable decision model and a durable handoff artifact, not merely familiarity with buttons. The lab tests the first, second, third, fifth, and sixth outcomes directly.

The Delivery Loop

graph LR
  A[Choose surface] --> B[Optimize locally]
  B --> C[Hand off]
  C --> D[Supervise cloud]
  D --> E[Security feedback]
  E --> F[Review and gate]
  F --> G[Return or merge]
This loop is the agenda and the central mental model. Review and security are not separate after-the-fact products. They are feedback mechanisms that can create another agent session or return the work to a developer. Point out that the loop can run more than once before merge.
1. Choose

Put the Work in the Right Place

The first optimization is choosing the execution surface. Sending every task to the cloud is not maturity. Matching task shape to agent type is.

One Job, Three Execution Surfaces

SurfaceBest FitContextInteraction
Local agentAmbiguous explorationWorkspace and local toolsSynchronous
Background agentIsolated implementationLocal machine or worktreeAsynchronous
Cloud agentBounded repository taskGitHub and configured cloud toolsAsynchronous
Emphasize that agent type describes where execution happens and which context is available. The cloud agent works in a GitHub Actions-powered ephemeral environment. It cannot see arbitrary local terminal state, unsaved files, or local-only services. This distinction controls the rest of the course.

The Delegation Decision

Stay Local

Requirements are changing, decisions require rapid feedback, or the task depends on unavailable local state.

Go to Cloud

Scope is bounded, context is durable, commands are reproducible, and completion can be checked.

Decision rule: delegate execution only after uncertainty has been reduced enough for asynchronous work.

Avoid framing cloud work as the destination for every task. A cloud agent is strongest when it can independently determine whether it is done. If the developer expects to answer questions every two minutes, the task is not ready for asynchronous execution.

Context Has a Border

TravelsDoes Not Automatically Travel
Transferred chat historyUnsaved editor content
Committed repository filesTransient terminal output
Repository instructionsLocal-only services and credentials
Configured MCP contextUnconfigured local tools
Issue and pull request contextAssumptions held only by the developer
The cloud boundary is the reason a handoff artifact matters. Transferring a conversation helps, but it does not make local runtime state available remotely. Durable context belongs in version-controlled files, an issue, or a clearly structured handoff packet.
2. Optimize

Prepare Before You Delegate

This is the core section requested for the redesign. Optimization means reducing setup discovery, ambiguity, and validation cost before a billable cloud session begins.

Optimize for a Short Feedback Loop

graph LR
  A[Clear scope] --> B[Fast setup]
  B --> C[Deterministic checks]
  C --> D[Small diff]
  D --> E[Useful review]
  • Reduce discovery the agent must repeat
  • Make success observable through commands
  • Keep the change within one repository, branch, and pull request
Optimization is not prompt polishing alone. It is repository engineering. A lock file, a fast test, and a stable setup command often improve results more than another paragraph of instructions. Smaller tasks also reduce AI Credit and Actions-minute consumption.
Lab Checkpoint

Is This Repository Agent-Ready?

  • Can a fresh environment install dependencies without guessing?
  • Are build, test, and lint commands documented and fast?
  • Do tests prove the acceptance criteria?
  • Are instructions specific and free of conflicts?
  • Are secrets, network destinations, and external tools bounded?
  • Can the task complete within the cloud session limit?
Learners create a repository-readiness audit at this point. The hard session maximum is 59 minutes, so a task that cannot set up and validate within that window must be reduced or prepared differently. A failed setup step does not stop the agent from starting, which makes explicit verification especially important.

Make Setup Deterministic

name: Copilot Setup Steps
on:
  workflow_dispatch:
  pull_request:
    paths: [.github/workflows/copilot-setup-steps.yml]

jobs:
  copilot-setup-steps:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: "22"
          cache: npm
      - run: npm ci
      - run: npm test
The file must be located at .github/workflows/copilot-setup-steps.yml on the default branch, and the job must be named copilot-setup-steps. Use least-privilege permissions. Replace the sample runtime and commands with those required by the demo repository. Validate the workflow through Actions before relying on it in an agent session.

Put Guidance at the Right Layer

ArtifactPurposeGood Content
copilot-instructions.mdRepository-wide standardsBuild, test, architecture, security
Path-specific instructionsScoped conventionsAPI, UI, test, or documentation rules
AGENTS.mdAgent-facing operational contextCommands, boundaries, workflow
Agent skillsReusable specialist workflowScripts, references, repeatable procedures
MCP configurationExternal context and toolsOnly the access required for the task
Avoid copying the same rule into every layer. Repository instructions should be short, universal, and actionable. Path-specific files narrow behavior where necessary. Skills package repeatable workflows. MCP expands the trust boundary and should be enabled deliberately.

Design the Cloud Boundary

Permit Deliberately

Required package registries, least-privilege agent variables, approved MCP servers, and isolated runners.

Assume Nothing

The integrated firewall is not comprehensive, does not cover MCP servers, and does not cover setup-step processes.

  • Never expose production credentials to a learning repository
  • Treat content exclusions as inapplicable to cloud agent execution
  • Use ephemeral, single-use infrastructure for self-hosted runners
This slide prevents a common misconception: the agent firewall is a useful control, not a complete security boundary. GitHub documents that it applies to processes started through the agent's Bash tool inside the Actions appliance. Setup steps and MCP servers require their own controls.
Lab Checkpoint

Build the Handoff Packet

# Objective
One observable outcome.

## Relevant context
Files, architecture, and prior decisions.

## Acceptance criteria
- Behavior that must be true
- Tests that must pass

## Validation
Exact build, test, lint, and scan commands.

## Constraints and non-goals
Security boundaries and work explicitly excluded.
The handoff packet can live in an issue, a planning document, or the transferred conversation. The lab stores it in docs/handoff.md so it can be validated before delegation. Ask learners to remove any requirement that cannot be objectively checked or resolved from available repository context.
3. Hand Off

Move Intent, Not Just a Prompt

The handoff begins locally because ambiguity is cheaper to resolve while the developer is present. Execution moves only after the plan and verification strategy are explicit.

Plan Locally

sequenceDiagram
  participant D as Developer
  participant P as Plan agent
  participant R as Repository
  D->>P: State objective and constraints
  P->>R: Inspect code and tests
  P-->>D: Propose bounded plan
  D->>P: Resolve ambiguity
  P-->>D: Final plan and checks
A local Plan agent can inspect the current workspace and ask for clarification before implementation begins. The learner should challenge assumptions, request file-level specificity, and ensure the plan names validation commands. Planning is complete when another agent can execute without relying on unstated decisions.
Handoff

Continue in the Cloud

  1. Review the local plan and save durable repository context
  2. Select Continue in Cloud from the Plan agent implementation control
  3. Choose Copilot cloud agent, the appropriate model, and any custom agent
  4. Confirm the target repository and branch context
  5. Let the session run asynchronously

Alternative paths: switch the active session type to Cloud, or use /delegate from a background agent session.

Current VS Code supports transferring the full local chat context into a cloud session. Point out that this transfers conversation context, not local runtime state. Deep research, planning, and iteration before pull-request creation are available in the GitHub.com cloud-agent experience; some integrations create a pull request directly.

Supervise Through Evidence

  • Read the proposed plan before accepting implementation direction
  • Watch setup-step output for missing tools or blocked downloads
  • Inspect commits and changed files for scope drift
  • Confirm which build, test, and lint commands actually ran
  • Use follow-up instructions when evidence contradicts the goal
  • Create the pull request only when the session is ready for review
Supervision should be evidence-driven. Avoid prescribing every edit after delegation. Instead, compare the agent's observable work to the handoff packet. Cloud sessions are visible in VS Code when they originate from GitHub issues or pull requests, which gives the developer a unified place to monitor them.

Recover at the Right Layer

FailureBest Response
Dependency cannot installRepair setup steps or firewall access
Agent misunderstood architectureImprove durable repository guidance
Task expanded beyond one outcomeStop and split the work
Implementation needs a small correctionGive a specific follow-up instruction
Approach is fundamentally wrongReturn local, revise the plan, and redelegate
Do not compensate for a broken repository with a longer prompt. Fix environment failures in environment configuration, context failures in durable instructions, and planning failures in task scope. This makes the next session better as well as the current one.
4. Secure

Turn Findings into Agent Work

Security now becomes another structured handoff. CodeQL detects and explains a data-flow or control-flow problem. Copilot cloud agent can receive that finding as the task context and attempt a validated remediation.
Lab Checkpoint

From Pull Request to Security Agent

graph LR
  A[Cloud agent PR] --> B[CodeQL scan]
  B --> C{Alert?}
  C -->|No| D[Review gates]
  C -->|Yes| E[Assign to Copilot]
  E --> F[Agentic remediation]
  F --> G[Rerun analysis]
  G --> H[Draft fix PR]
This is the central cloud-security interface. The original implementation session and the security remediation session are distinct. Agentic Autofix can also begin from an alert backlog or a security campaign, where between one and 25 selected alerts can be assigned together.

CodeQL Detects. Agents Remediate.

CapabilityRoleOutput
CodeQLDeterministic static analysisAlert and data-flow evidence
Copilot AutofixOne-step suggested correctionProposed fix
Agentic AutofixCloud-agent remediation loopValidated draft pull request
Copilot code reviewContextual pull-request reviewReview comments
Code QualityQuality, coverage, and debt controlsFindings and merge gates
Use the phrase CodeQL and security agents, not CodeQL agent, when precision matters. CodeQL itself is the analysis engine. Agentic Autofix uses Copilot cloud agent to explore relevant files, implement a fix, and rerun the original analysis.

What Agentic Autofix Actually Does

  1. Receives one or more code-scanning alerts as task context
  2. Explores relevant files across the repository
  3. Generates a repository-aware correction
  4. Reruns CodeQL or the original analysis
  5. Iterates when the result still fails
  6. Opens a draft pull request with validation evidence

Availability: public preview; requires cloud agent, Copilot Autofix, and eligible GitHub security licensing.

As of July 2026, agentic Autofix supports first-party and third-party code-scanning alerts. Typical fix generation is measured in minutes, not seconds. It consumes AI Credits and GitHub Actions minutes. Do not claim that it always fixes an alert successfully.

Trust the Evidence, Then Review the Code

  • Confirm the original alert is absent from the rerun
  • Inspect the complete data flow, not only the reported line
  • Run functional and regression tests
  • Check for behavior changes introduced by sanitization or validation
  • Review dependencies, permissions, and new network access
  • Ask Copilot to iterate when the fix is incomplete or overbroad

Validation is best effort. An unresolved or unverifiable result must remain visible to the reviewer.

Closing the CodeQL alert proves that the original query no longer detects the path. It does not prove complete application correctness. Human review should consider bypasses, alternate paths, functional regressions, and whether the remediation changed the intended behavior.
5. Gate

Return Control to the Team

The final phase combines machine feedback with accountable human approval. Automation establishes a consistent floor. It does not become the approver of its own work.
Lab Checkpoint

Build a Layered Review Gate

LayerQuestionEnforcement
Tests and lintDoes the change behave as intended?Required checks
Code scanningDid it introduce a known security path?Severity threshold
Code QualityDid quality or coverage regress?Quality threshold
Copilot reviewWhat contextual concerns remain?Review comments
Human reviewShould this change enter the product?Required approval
Rulesets can require code-scanning results and define thresholds such as critical, high or higher, medium or higher, or all. Code Quality rulesets can enforce quality and coverage criteria. Copilot code review provides comments, while required human approval remains the accountable merge decision.

Know When to Return Local

graph LR
  A[Cloud PR] --> B{Evidence complete?}
  B -->|Yes| C[Human approval]
  B -->|Small gap| D[Cloud iteration]
  B -->|Needs local state| E[Checkout branch]
  E --> F[Local debug and test]
  F --> G[Push to same PR]
  G --> B
A return handoff is not a failure. Local debugging is appropriate when the task needs interactive inspection, unavailable hardware, private test environments, or rapid experimentation. Preserve the same pull request when possible so the review and security record stays coherent.

Operate the Loop Deliberately

  • One cloud session changes one repository and one branch
  • One task produces exactly one pull request
  • Sessions have a maximum execution time of 59 minutes
  • Cloud agent and code review consume AI Credits and Actions minutes
  • Repository rules must permit agent branch operations without bypassing final approval
  • Measure merged outcomes, review cycles, time to merge, and remediation quality
End with operating discipline. Cost is shaped by model choice, token use, setup time, validation work, and repeated sessions. GitHub provides usage metrics for cloud-agent pull-request outcomes. Teams should track whether delegation improves throughput and quality rather than counting sessions alone.
Challenge Complete

Delegate Execution, Keep Accountability

Prepare, hand off, inspect, secure, and decide.

Recap the completed loop. The learner chose an execution surface, optimized the repository, built a handoff packet, delegated a local plan, inspected cloud evidence, used CodeQL as a security feedback source, and preserved human approval. The durable takeaway is that successful cloud-agent work begins before delegation.
